## 2. 修订动机

V1.0 上线后用户反馈：**多人共用一台电脑时数据无法隔离**，且**缺乏账号体系**导致无法支撑后续多设备同步、共享账本等场景。V1.0.1 先用最小成本把账号体系搭起来：

- **本地账号**：账号信息本地存储，不依赖后端，可立即上线
- **导入导出**：通过 JSON 文件实现跨设备数据迁移（替代真后端）
- **密码不限制复杂度**：产品初期信任用户；V2.0 再强化

## 4. 新增功能详情

### F9：用户注册

| 维度 | 详细说明 |
| --- | --- |
| 入口 | 首次访问应用 → 自动跳转登录页 → 点击「没有账号？立即注册」 |
| 表单字段 | ①用户名（必填，3-20 位，仅字母数字下划线中文，首字符不能为下划线）；②密码（必填，1-64 位，无强度限制）；③确认密码（必填，必须与密码一致） |
| 用户名唯一性 | 注册时检查 localStorage 中 `ma_users` 索引，已存在则 Toast「用户名已被占用」 |
| 密码存储 | 使用浏览器 `crypto.subtle`（PBKDF2-SHA256，100000 次迭代 + 随机 salt）哈希后存储；**明文密码永不入库，永不上传** |
| 字段持久化 | 注册成功后写入 `ma_users` 列表，同时初始化该用户的「个人账本」与默认分类 |
| 异常 | 用户名非法 / 已存在 / 两次密码不一致 → Toast 提示，按钮置灰直到修正 |
| 验收 | 重复用户名无法注册；密码错误无法登录同名账号；注册成功后自动登录并进入首页 |

### F10：用户登录

| 维度 | 详细说明 |
| --- | --- |
| 入口 | 顶部 Tab 切换、刷新页面、退出后再次访问 |
| 表单字段 | ①用户名（必填）；②密码（必填） |
| 凭据校验 | 取 `ma_users` 中对应用户，PBKDF2 重算哈希与存储对比；不匹配则 Toast「用户名或密码错误」（不区分两者以防枚举） |
| 登录态 | 成功后写入 `ma_currentUserId` 到 localStorage，并触发 `auth:login` 自定义事件 |
| 自动登录 | 仅在本次会话内有效，刷新页面需重新登录（出于安全考虑，V1.0.1 不做长效 token） |
| 异常 | 连续 5 次失败 → 弹窗冷却 30 秒（防爆破） |
| 验收 | 正确凭据可登录；错误凭据 Toast 提示；登录态可被登出清除 |

### F11：退出登录 / 切换账号

| 维度 | 详细说明 |
| --- | --- |
| 入口 | 「我的」页底部「退出登录」按钮 |
| 行为 | 清空 `ma_currentUserId`，触发 `auth:logout` 事件，跳转登录页 |
| 切换账号 | 在登录页底部显示「切换账号」入口，本质等于退出后选择另一用户登录 |
| 重要确认 | 退出前二次确认弹窗：「退出后当前账本数据仍保留在本机，下次登录可继续访问」 |
| 验收 | 退出后任何受保护页面均自动跳转登录页 |

## 5. 受影响的现有功能

### 5.1 首次访问流程（变更）

| V1.0 | V1.0.1 |
| --- | --- |
| 首次访问 → 引导页 → 「开始使用」直接进首页 | 首次访问 → **登录页** → 注册或登录后才能进首页 |

### 5.2 数据隔离（新增）

- 所有 `ma_books / ma_records / ma_categories / ma_budgets` 数据新增隐式关联 `ownerId`
- 查询时自动过滤当前用户的数据；切换账号后看到完全不同的账本列表
- 旧版 V1.0 数据（无 `ownerId`）迁移策略：登录后弹窗提示「检测到旧版本地数据，是否导入到当前账号？」

### 5.3 数据导出（调整）

- 导出 JSON 新增顶层字段 `ownerId` 与 `exportedAt`
- 导出当前账号数据时，包含 `ownerId` 用于跨设备识别
- 导入时校验 `ownerId`：相同 `ownerId` 才能合并到当前账号；不同则弹窗「数据来自其他账号，是否创建新账号或合并？」

### 5.4 「我的」页（调整）

| V1.0 | V1.0.1 |
| --- | --- |
| 显示「记账小助手」+ 当前账本 | 显示**当前用户名**（带头像首字符）+ 当前账本 + 「退出登录」按钮 |

## 6. 数据模型增量

### 6.1 User 实体升级

**V1.0**（无密码字段）：
```ts
User {
  id: string
  nickname: string
  createdAt: datetime
}
```

**V1.0.1**（新增认证字段）：
```ts
User {
  id: string                    // 内部 ID
  username: string              // 登录用户名（唯一）
  displayName: string           // 显示昵称（默认 = username）
  passwordHash: string          // PBKDF2 哈希（hex）
  passwordSalt: string          // 随机 salt（hex，16 字节）
  passwordIterations: number    // PBKDF2 迭代次数（默认 100000）
  createdAt: datetime
  lastLoginAt: datetime?
}
```

### 6.2 实体关联调整

| 实体 | 变化 |
| --- | --- |
| `AccountBook` | 新增 `ownerId: string`（账本所有者） |
| `Record` | 已有的 `createdBy: string` 直接复用为 `ownerId` |
| `Category` | 预置分类改为全局模板，每个用户首次登录时拷贝到自己名下 |
| `Budget` | 新增 `ownerId: string`（冗余存储，便于筛选） |

### 6.3 localStorage Key 变化

| Key | 变化 |
| --- | --- |
| `ma_currentUserId` | 新增 |
| `ma_users` | 新增（账号索引列表） |
| `ma_books / ma_records / ma_budgets` | 不变（按 ownerId 过滤） |
| `ma_categories` | 不变（首次登录时按用户隔离拷贝） |
| `ma_session` | 删除（不再需要 onboarding 标志） |

## 7. 关键流程

### 7.1 注册流程

```
首次访问
  → 跳转登录页
  → 用户点击「立即注册」
  → 填写用户名/密码/确认密码
  → 前端校验（格式 + 唯一性）
  → crypto.subtle PBKDF2 计算哈希
  → 写入 ma_users
  → 自动登录（设置 ma_currentUserId）
  → 初始化个人账本与默认分类
  → 跳转首页
```

### 7.2 登录流程

```
任意页面访问（含刷新）
  → 检查 ma_currentUserId
  → 若不存在 → 跳转登录页
  → 若存在但 ma_users 中找不到该用户（数据被外部清掉）→ 清空 session + 跳转登录页
  → 输入用户名 + 密码
  → PBKDF2 重算哈希对比
  → 成功 → 写入 ma_currentUserId + 更新 lastLoginAt → 跳转原页面或首页
  → 失败 → 计数 +1，超过 5 次 → 冷却 30 秒
```

### 7.3 数据迁移流程（旧 V1.0 用户）

```
已登录账号访问
  → 检查 ma_books / ma_records 等是否存在 ownerId = null 的记录
  → 若有 → 弹窗「检测到旧版数据」
       → 选项 A：导入到当前账号（自动给所有数据打上当前 ownerId）
       → 选项 B：创建新账号（不导入）
       → 选项 C：丢弃（删除旧数据）
```

## 9. 安全考虑

| 维度 | 措施 |
| --- | --- |
| 密码存储 | PBKDF2-SHA256 + 100000 迭代 + 随机 salt；明文不入库 |
| 传输安全 | V1.0.1 纯本地，无网络传输；HTTPS 仅用于静态资源托管 |
| 防爆破 | 连续 5 次失败冷却 30 秒 |
| 用户名枚举 | 登录失败统一提示「用户名或密码错误」 |
| 数据隔离 | 所有业务数据按 `ownerId` 过滤，账号间完全不可见 |
| 退出登录 | 清空 session key，防止他人复用浏览器会话 |
| 已知局限 | V1.0.1 不做「找回密码」—— 忘记密码只能「重置本地数据」（弹窗明确告知） |

## 10. 非功能需求增量

| 维度 | 指标 |
| --- | --- |
| 注册耗时 | PBKDF2 计算 100000 次约 100-500ms，整体注册流程 ≤ 2s |
| 登录耗时 | 单次登录 ≤ 1s（含哈希计算） |
| 账号容量 | localStorage 容量约 5MB，单账号 1KB 数据 → 可支持 1000+ 用户 |
| 数据隔离正确性 | 不同账号登录后，看不到任何对方账号的数据（账本/记录/分类/预算） |
| 兼容性 | 旧 V1.0 数据需提供迁移路径（不能直接清空） |

## 11. 验收标准增量（V1.0.1）

**功能性**
- [ ] 未登录访问任何业务页面均跳转登录页
- [ ] 注册：用户名格式校验、唯一性校验、密码一致性校验均生效
- [ ] 注册成功后自动登录并初始化账本
- [ ] 登录：5 次错误后冷却 30 秒
- [ ] 退出登录：清空 session 后无法访问业务页面
- [ ] 切换账号：A 账号退出后 B 账号登录，看不到 A 的任何数据
- [ ] 数据迁移：旧 V1.0 数据导入流程可走通

**安全**
- [ ] localStorage 中搜不到任何明文密码
- [ ] 错误密码登录提示统一为「用户名或密码错误」，不区分两者
- [ ] 退出登录后 `ma_currentUserId` 已被清除

**体验**
- [ ] 登录 / 注册页移动端无横向滚动
- [ ] 登录 / 注册页在 Safari / Chrome / 微信内置浏览器均能正常输入密码
- [ ] 旧 V1.0 用户首次进入 V1.0.1 看到迁移提示，不直接丢失数据

## 13. 账号恢复（F12 增补）

> 本章为 V1.0.1 的补充设计，专门解决「忘记密码 / 数据丢失 / 误删」场景。
> 适用于 2026-10-05 增补，文档版本号不变（仍为 V1.0.1）。

### 13.1 背景与原则

V1.0.1 是**纯本地账号体系**，没有邮箱 / 手机号等验证手段，因此：

| 原则 | 说明 |
| --- | --- |
| **不做密码找回** | 没有验证渠道，「找回」等于「重置」，会丢失数据 |
| **不做云端备份** | V2.0 才提供，V1.0.1 仅靠用户主动导出 |
| **预防优于补救** | 设计上引导用户「定期备份」，让数据有逃生舱 |
| **补救必须明确** | 任何补救操作必须二次确认，并清楚告知「将丢失什么」 |

### 13.2 功能详情

#### F12-A：忘记密码入口（说明型，非找回）

| 维度 | 详细说明 |
| --- | --- |
| 入口 | 登录页 → 「忘记密码？」链接 |
| 行为 | **不重置密码**。弹出说明卡片，三选一引导用户： |
| 选项 1 | 「我之前导出过备份」→ 跳转到 F12-C 从备份恢复 |
| 选项 2 | 「我还想用这个用户名」→ 跳转到 F12-B 重置账号 |
| 选项 3 | 「我重新注册一个」→ 直接跳转注册页 |
| 文案 | 必须明确告知：「本应用是本地存储，没有云端，无法通过邮箱/短信找回密码。如未备份，请做好数据丢失的心理准备。」 |
| 验收 | 入口可达；三选项均跳转正确；文案显著、不藏在小字里 |

#### F12-B：账号重置（保留用户名，清空数据）

| 维度 | 详细说明 |
| --- | --- |
| 入口 | F12-A → 选项 2 |
| 表单字段 | ①输入要重置的用户名（必填，必须存在于 `ma_users`）；②设置新密码（必填）；③确认新密码（必填） |
| 校验 | 用户名不存在 → Toast「该用户名不存在」；两次密码不一致 → 按钮置灰 |
| 删除范围 | 从 `ma_users` 删除该用户；从 `ma_books / ma_records / ma_budgets` 删除 `ownerId = 该用户` 的所有记录；从 `ma_categories` 删除该用户创建的自定义分类（保留预置分类的备份） |
| 写入 | 用原用户名 + 新密码哈希重建账号（让用户能重新用同名账号登录） |
| 二次确认 | 输入用户名后立即弹窗：「重置账号「小李」将永久删除以下数据：X 个账本、Y 条记录、Z 个自定义分类。此操作不可恢复。是否继续？」 |
| Toast | 完成后：「账号已重置，请使用新密码登录」 |
| 验收 | 重置后原账号无法用旧密码登录；用新密码可登录同名账号；所有原数据已清除；预置分类保留（重置后会自动重新初始化） |

#### F12-C：从备份恢复

| 维度 | 详细说明 |
| --- | --- |
| 入口 | F12-A → 选项 1；登录页底部「从备份恢复」链接；「我的」→「数据管理」 |
| 输入 | 用户选择本地 JSON 备份文件（V1.0 / V1.0.1 格式均需兼容） |
| 解析校验 | ①JSON 格式合法；②顶层包含 `version` 与 `ownerId`；③`ownerId` 与 `username` 对应 `ma_users` 中某条记录或为新用户 |
| 三种结果 | |
| → 新用户备份 | `ownerId` 不存在于 `ma_users` → 自动用备份中的 username 注册并恢复所有数据 → 直接登录 |
| → 同名账号备份 | `ownerId` 已存在 → 弹窗三选一：覆盖（删除现有数据后导入）/ 合并（保留两边数据，去重）/ 取消 |
| → 无效备份 | JSON 损坏或非本应用格式 → Toast「备份文件无效」并引导查看示例 |
| 合并去重策略 | 记录按 `id` 去重；同 `id` 保留最新 `updatedAt`；账本按 `id + name` 去重；分类按 `id` 去重 |
| 进度提示 | 数据量大（>1000 条）时显示进度条；完成后 Toast「已恢复 X 条记录、Y 个账本」 |
| 验收 | 新用户备份可自动恢复；同名账号三种选择都生效；非法文件不报错崩溃；预置分类缺失时自动补充 |

#### F12-D：定期备份提醒

| 维度 | 详细说明 |
| --- | --- |
| 触发 | 当前用户上次备份（导出 JSON）距今 ≥ 7 天 |
| 显示位置 | 「我的」页顶部，紧邻用户名卡片，黄色提示条样式 |
| 文案 | 「你已 X 天未备份，建议立即备份以防数据丢失」 |
| 操作 | 「立即备份」→ 触发 V1.0 的导出 JSON 流程；「我知道了」→ 关闭本次提示 7 天 |
| 关闭策略 | 「我知道了」记录到 `ma_lastBackupDismiss`，7 天内不再提示；点过「立即备份」后无论成败都重置计时 |
| 关闭入口 | 「不再提醒」长按 3 秒触发，永久关闭（设置项） |
| 验收 | 注册后 7 天无备份 → 提示出现；备份后立即消失；「我知道了」后 7 天不再出现 |

#### F12-E：首次注册后的备份教育

| 维度 | 详细说明 |
| --- | --- |
| 触发 | 注册成功 + 自动登录后 |
| 显示 | 浮层（非阻塞），可在 3 秒后自动消失或点 X 关闭 |
| 文案 | 「账号已创建！由于数据存在本地浏览器，建议立即备份账号，避免忘记密码后无法恢复。」 |
| 操作 | 「立即备份」→ 触发导出 JSON；「下次再说」→ 关闭（不重复打扰） |
| 兜底 | 关闭后由 F12-D 的 7 天提醒机制兜底 |
| 验收 | 仅注册成功后显示一次；导出后下次注册新账号仍会显示 |

### 13.3 数据模型增量

| Key | 类型 | 说明 |

### 13.4 安全考虑

| 风险 | 措施 |
| --- | --- |
| 重置账号被滥用 | 必须输入原用户名 + 设置新密码，相当于「声明拥有」+「创建新密码」双重动作；不可绕过 |
| 备份文件被劫持 | 备份文件不含密码哈希（仅含 ownerId + 数据），但导入时仍校验 ownerId 与 username 一致性 |
| 误删数据 | 所有删除操作（二次确认、清空）必须二次确认；F12-D 提醒让用户形成备份习惯 |
| 备份合并冲突 | 合并时记录按 `id + updatedAt` 去重，账本按 `id + name`，避免误覆盖 |
